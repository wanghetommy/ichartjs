# iChart.js 2.0 Final Release Readiness

Date: 2026-09-16

## Decision

The repository runtime is technically ready for a final release candidate, but it must not be published or tagged as `2.0.0` yet. The source remains `2.0.0-rc.1` until the release blockers below are closed.

iChart.js 2.0 is a new Agent-first product line. Compatibility with 1.x and a 1.x-to-2.0 migration guide are intentionally outside the release scope.

## Release Blockers

1. **Missing final version and tag.** No repository release tag exists. Create the final commit and tag only after the version is changed consistently in `package.json`, `src/index.mjs`, and the changelog.
2. **Default branch cutover.** GitHub still uses `master`, which currently points to the archived 1.x project and its legacy development dependencies. The final 2.0 commit must fast-forward `master` before the GitHub Release is created.
3. **Native Safari acceptance.** Safari 26.6.2 is installed, but Safari's Allow Remote Automation setting is disabled. WebKit 26 passed, but it does not replace a native Safari gate.
4. **Physical-device acceptance.** Real iOS/Android touch behavior and representative release-host performance budgets remain external gates.

## Deferred npm Publication

The public npm name `ichartjs` currently resolves to an npm security holding package, and this machine has no authenticated publisher. Per the release decision, npm publication is deferred and does not block the GitHub source release.

## Finalization Order

1. Enable Safari Allow Remote Automation and run the native Safari suite.
2. Record physical-device and representative release-host acceptance.
3. Change `2.0.0-rc.1` to `2.0.0` in package metadata, runtime metadata, and changelog in one change.
4. Re-run all automated, package-consumer, and browser gates.
5. Commit the final version and fast-forward `master` to the same commit.
6. Create and push the `v2.0.0` tag, then create the GitHub Release from that exact commit.
